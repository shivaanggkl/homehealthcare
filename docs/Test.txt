**Best Testing Order**
Test in this order or many later pages will just show empty states:
1. Auth and settings
2. Setup and catalogs
3. Branches and users
4. Patients
5. Workforce
6. Scheduling
7. Mobile + EVV

11. Compliance
12. Patient events
13. Goals
14. Revenue readiness
15. Analytics

**What To Expect Before Data Exists**
Many pages are correctly empty at first. That is normal. Expect:
- list pages show empty or onboarding-style states
- detail routes with IDs are best reached by clicking from list pages, not typing random IDs
- command-center pages will stay sparse until upstream records exist
- route guards show denied states if the logged-in user lacks permission

**How To Know A Page Is Working**
A page is healthy if:
- it loads without console/network failures
- empty states are intentional and understandable
- save/update/delete actions show a clear success or error state
- links route into the correct downstream page
- denied pages show access-denied UI rather than broken UI
- lists reflect new records after mutation or refresh
- command-center pages become richer as upstream data is added

**Best Practical Way To Test Everything**
Use one dataset and keep building on it:
1. Create branch
2. Create service line and visit type
3. Create patient
4. Create caregiver
5. Create scheduled visit
6. Run mobile visit + EVV
7. Submit documentation
8. Review it
9. Create compliance reminders/events/goals
10. Open revenue readiness
11. Open analytics

That single chain unlocks most of the later pages.
