Epic 6 Frontend Backlog
HomeHealthCare

Purpose

This document converts Epic 6 from `Requirements.txt` into a frontend delivery backlog for the caregiver mobile application.

Epic 6 title

Caregiver mobile app

Epic 6 feature scope from the requirements

- secure login
- today’s visits
- route/order of visits
- patient summary
- care instructions
- start visit / end visit
- GPS proof
- offline-first support
- signature capture
- task checklist
- quick notes
- photo uploads
- incident flagging
- message center

Planning assumptions

- Epic 1 frontend and backend are complete and provide auth, session, RBAC, protected-route, and audit-view patterns
- Epic 3 patient workflows are complete and provide patient summary data that can be projected into mobile-safe visit context
- Epic 4 workforce workflows are complete and provide caregiver identity and availability context
- Epic 5 scheduling workflows are complete and provide assigned visit, route-order, and open-shift resolution data that the mobile app consumes
- Epic 6 frontend is a caregiver-facing mobile experience, not an admin web scheduling workspace
- Epic 6 should feel mobile-first and task-oriented, not like a smaller copy of the desktop admin UI
- offline-first behavior should prioritize safe local capture, explicit sync states, and recoverable retries
- Epic 6 should stop short of the deeper EVV exception/compliance workflows that belong to Epic 7

Status legend

- BLOCKED: frontend should wait for the corresponding Epic 6 backend APIs

FE6-01 — Mobile app navigation and caregiver information architecture
Related Epic 6 features: all
Backend status: BLOCKED

Story
As a caregiver, I want a simple mobile navigation model so I can move between today’s work, visit details, messages, and field tasks quickly.

Frontend acceptance criteria

- caregiver mobile app has a dedicated mobile navigation shell
- navigation is optimized for handheld use
- routes are grouped by caregiver field workflows
- unauthorized or unsupported deep links render controlled states
- today-work, visit detail, message center, and task capture flows are easy to reach with minimal taps

Definition of done for Epic 6 frontend

Epic 6 frontend is done only when:

- caregiver mobile work is reachable through a dedicated mobile app shell
- today-work, visit detail, start/end visit, task checklist, note, photo, signature, incident, and message-center screens use backend APIs rather than placeholder local state
- offline or low-connectivity behavior is understandable and recoverable for representative field actions
- validation, sync, conflict, and unauthorized errors are shown clearly
- sensitive patient and visit data is presented in a privacy-aware mobile form
- the mobile experience remains usable on common phone-sized screens
- core Epic 6 mobile screens are regression-covered
