Epic 15 Backend Backlog
HomeHealthCare

Purpose

This document converts Epic 15 from `Requirements.txt` into a backend delivery backlog.

Epic 15 title

Dashboard and analytics

Epic 15 feature scope from the requirements

- today’s visits
- unfilled visits
- late starts
- missed visits
- documentation aging
- QA backlog
- caregiver utilization
- branch performance
- revenue readiness count
- compliance exceptions

Planning assumptions

- Epic 1 is complete and provides auth, session management, RBAC, tenancy, audit, branch-aware authorization, and notification foundations
- Epic 3 through Epic 14 are complete enough to provide the source domain data that Epic 15 aggregates rather than redefines
- Epic 5 provides schedule, visit, open-shift, and staffing context used for today’s visits, unfilled visits, and late-start metrics
- Epic 7 provides missed-visit and EVV exception context relevant to operational dashboard signals
- Epic 8 provides documentation record state and timing needed for documentation aging metrics
- Epic 10 provides QA backlog and review-work metrics
- Epic 11 provides compliance exception and dashboard-ready compliance state
- Epic 14 provides revenue-readiness state for financial-operational summary metrics
- Epic 15 focuses on analytics-ready projections and dashboard aggregation, not operational mutation workflows already covered by earlier epics
- analytics should prioritize operational usefulness, fast queryability, and branch-aware visibility over deep BI tooling or ad hoc report builders in the first pass

Scope rule

- Include only Epic 15 backend work
- Cover dashboard metric definitions, aggregation projections, branch and role-aware summary APIs, trend/history support where practical, authorization, audit, and tests
- Do not include frontend-only tasks
- Do not pull custom report builder, data warehouse, or unrelated workflow mutation scope into Epic 15

Definition of done for Epic 15 backend

Epic 15 backend is done only when:

- metric definitions, snapshots, branch-performance summaries, utilization summaries, backlog summaries, and readiness/compliance summaries exist with clear source-of-truth rules
- dashboard, drilldown, branch-performance, and caregiver-utilization APIs are available for real operational use
- metric refresh and dashboard snapshot actions are implemented through audited APIs
- operational, QA, compliance, and revenue-readiness counts are available through structured backend contracts
- role-based authorization and tenant or branch-aware privacy rules are enforced for analytics data
- dashboard drilldown and summary outputs are queryable through backend APIs suitable for command-center use
- dashboard aggregation is deterministic and derived from source records rather than ad hoc frontend logic
- core Epic 15 analytics flows are regression-covered
