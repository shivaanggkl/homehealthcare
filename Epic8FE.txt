Epic 8 Frontend Backlog
HomeHealthCare

Purpose

This document converts Epic 8 from `Requirements.txt` into a frontend delivery backlog for notes, forms, and task completion.

Epic 8 title

Notes, forms, and task completion

Epic 8 feature scope from the requirements

- visit note templates by visit type
- structured tasks and free text
- required-field enforcement
- quick save / draft handling
- attachments/photos
- reusable task libraries
- printable summaries
- role-based forms

Planning assumptions

- Epic 1 frontend and backend are complete and provide auth, session, RBAC, protected-route, and audit-view patterns
- Epic 3 frontend and backend are complete and provide patient workspace, attachment visibility, and patient context used inside documentation
- Epic 5 frontend and backend are complete and provide visit/schedule context
- Epic 6 frontend and backend are complete and provide caregiver mobile execution, quick notes, artifact capture, and offline sync patterns
- Epic 7 frontend and backend are complete and provide EVV/missed-visit/exception outcomes that documentation can reference but should not duplicate
- Epic 8 frontend should support both caregiver-facing documentation capture and admin-side template management
- Epic 8 should stop short of generalized messaging from Epic 9, dedicated QA review workspaces from Epic 10, and broader goals/care-plan progression workflows from Epic 13
- printable summaries should render from backend summary contracts, not ad hoc client-only reconstruction
- role-based forms should stay explicit and understandable, not hide required work behind confusing dynamic behavior

Status legend

- BLOCKED: frontend should wait for the corresponding Epic 8 backend APIs

FE8-01 — Documentation information architecture and route model
Related Epic 8 features: all
Backend status: BLOCKED

Story
As a caregiver, coordinator, or admin, I want notes, forms, tasks, and print views to fit naturally into the visit and admin workflows so documentation work is coherent instead of scattered.

Frontend acceptance criteria

- caregiver-facing documentation routes exist within visit workflows
- admin-facing routes exist for template and task-library management
- documentation routes distinguish:
  - draft editing
  - submitted/read-only summary
  - printable summary
  - template configuration
- unsupported or unauthorized documentation routes render controlled states
- documentation status is visible without overwhelming the user with backend detail

Definition of done for Epic 8 frontend

Epic 8 frontend is done only when:

- note templates, task libraries, and visit documentation are reachable through coherent admin and visit-facing routes
- template editing, draft save, task completion, submission, attachment linkage, and printable-summary flows use real backend APIs rather than placeholder local state
- required-field and task validation is shown clearly with understandable draft vs submit behavior
- caregivers can tell when documentation is draft, incomplete, submitted, or read-only
- coordinator-facing documentation visibility exists for authorized users
- privacy-sensitive patient and internal metadata is minimized appropriately
- documentation screens are mobile-safe where field staff use them
- core Epic 8 screens are regression-covered
