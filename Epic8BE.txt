Epic 8 Backend Backlog
HomeHealthCare

Purpose

This document converts Epic 8 from `Requirements.txt` into a backend delivery backlog.

Epic 8 title

Notes, forms, and task completion

Epic 8 feature scope from the requirements

- visit note templates by visit type
- structured tasks and free text
- required-field enforcement
- quick save / draft handling
- attachments/photos
- reusable task libraries
- printable summaries
- role-based forms

Planning assumptions

- Epic 1 is complete and provides auth, session management, RBAC, tenancy, audit, branch-aware authorization, and notification foundations
- Epic 3 is complete and provides patient records, attachments, diagnoses, payer context, and patient-specific data needed inside visit documentation
- Epic 4 is complete and provides caregiver workforce context and role-based assignment information
- Epic 5 is complete and provides visit, recurrence, schedule state, and assignment context
- Epic 6 is complete and provides caregiver mobile execution, artifact upload, field notes, and sync-aware mobile workflows
- Epic 7 is complete and provides EVV, missed-visit, exception, and verification outcomes that documentation must respect
- Epic 8 focuses on structured visit documentation and task completion, not generalized messaging from Epic 9, QA review queues from Epic 10, or broader care-plan/goals workflows from Epic 13
- Epic 8 should support both field capture and office-side completion without forcing agencies into one documentation style
- printable summaries should expose a backend-ready structured export or render contract, not require a separate document engine product in this epic

Scope rule

- Include only Epic 8 backend work
- Cover note template, form template, task library, task completion, draft/final note state, required-field enforcement, attachment linkage, printable summary contracts, APIs, authorization, audit, and tests
- Do not include frontend-only tasks
- Do not pull messaging, QA queue, compliance dashboard, goals/interventions, or billing workflow scope from later epics into Epic 8

BE8-01 — Define documentation and task-completion domain architecture
Related Epic 8 features: all
Current status: NOT STARTED

Story
As the platform architect, I need a coherent documentation domain so notes, forms, tasks, drafts, and printable outputs follow one lifecycle and audit model.

Recommended acceptance criteria

- Epic 8 entities are defined explicitly, including:
  - visit note template
  - form template
  - reusable task library item
  - task set or note-template task instance
  - visit documentation record
  - visit note section or field response
  - note draft / submission state
  - printable summary projection
- lifecycle states are defined for at least:
  - draft
  - in_progress
  - submitted
  - amended optional
  - locked optional for later QA or billing use
- ownership and linkage rules are documented across visit, patient, caregiver, branch, visit type, and service line
- required-field and role-based visibility rules are documented
- audit expectations are defined for template changes, documentation saves, submission, amendment, attachment linkage, and printable summary generation

Definition of done for Epic 8 backend

Epic 8 backend is done only when:

- note templates, form structures, reusable task libraries, documentation records, structured responses, and attachment linkage exist with clear lifecycle rules
- draft-save and submit behavior are both implemented and intentionally different
- required-field enforcement is available through structured backend validation
- role-based and branch-aware authorization is enforced for templates and documentation records
- printable-summary contracts are available for completed visit notes
- documentation APIs use real backend models rather than placeholder storage
- documentation and template changes are audit-visible
- core Epic 8 documentation flows are regression-covered
